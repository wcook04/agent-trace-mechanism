# Example records

For the interactive README walkthrough, choose [checkout-review](checkout-review) as the Codex home. Its three synthetic recordings capture a failing rounding assertion, a correction and a successful retry.

The current MCP examples follow. They contain selected records from real work;
their provenance files describe what was retained or omitted. The inspection
commands read these records without executing the commands recorded inside them.

| Records | What to inspect | Command from the repository root |
|---|---|---|
| [validation-history.jsonl](validation-history.jsonl) | Failed tests, a correction and a retry | `python tools/inspect_recorded_run.py` |
| [launch-review/](launch-review/) | A coordinator and two Codex subagents | `python tools/inspect_agent_tree.py` |
| [cross-provider/](cross-provider/) | Claude reading Codex findings through MCP | `python tools/inspect_cross_provider.py` |
| [native-command.jsonl](native-command.jsonl) | Search followed by retrieval of one command's output | `python tools/record_native_contract.py --check` |

Use the Python environment installed by [the setup guide](../README.md#try-it).
[native-command-response.json](native-command-response.json) is generated by
`record_native_contract.py`; `--check` verifies it without changing it.

The remaining files preserve earlier parser and export behaviour:

- `codex.jsonl` is a synthetic transcript fixture. Its `.compact.txt`,
  `.detailed.txt` and `.expected.json` siblings are generated expectations.
- [controlled-run/](controlled-run/) and [codex-retrieval/](codex-retrieval/)
  retain earlier recordings and derived views. Their guides describe the
  [controlled run](../docs/controlled-run.md) and
  [retrieval recording](../docs/codex-retrieval.md).
- `production-structured-clip.json` preserves a desktop export; its
  [provenance](../docs/structured-clip-provenance.json) describes the selection.
- `retrieval-costs.json` holds recorded measurements, not performance guarantees.

`tools/regenerate_examples.py` owns the legacy generated views and indexes.
Run it with `--check` to detect drift. Synthetic Claude parser fixtures live in
`tests/fixtures/`; they are test inputs, not recordings of a Claude session.
