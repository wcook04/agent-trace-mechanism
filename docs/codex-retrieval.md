# Codex retrieves a different chat

On 2 November 2026, a Codex desktop chat using Sol calculated a fictional repair café budget with one Python command. A separate Sol subagent used the installed Agent Trace MCP tools to recover the opening time and budget. Its prompt contained the source ID and the question, not the facts it was asked to recover.

The coordinator then changed the source chat’s opening time from 10:00 to 10:30 and told the reader only that the source had changed. The reader called the same compact scope again, found the correction, and reread the earlier snapshot by hash. Its equality check returned true: the old text stayed unchanged.

The native plugin receipts are separate historical evidence: [first compact](../examples/codex-retrieval/native-codex-compact.json), [second compact](../examples/codex-retrieval/native-codex-compact2.json), [first detailed](../examples/codex-retrieval/native-codex-detailed.json), [second detailed](../examples/codex-retrieval/native-codex-detailed2.json). They were captured before the delegation-input parser repair. They retain the old missing-call warning: the app delivered a request in a `codex_delegation` envelope without a call ID. The repaired parser recognizes that exact delivery shape as input and records its provenance. Ordinary orphan results remain explicitly incomplete.

Injected instructions, environment data, workspace paths and the coordinator ID were removed or replaced in published receipts. Their original hashes, offsets and sizes identify the unpublished original responses, **not the edited public files**. The [selection receipt](../examples/codex-retrieval/selection.json) describes retained source records and replacements. The original logs were not modified. This is selected evidence, not a lossless export of either original chat.

## What you can reproduce

`python tools/demo_codex.py` starts the public MCP server as another process, searches the supplied manifest, reads a compact view, supplies the later recorded source, reads the same scope again, and verifies old-snapshot stability. It also requests the detailed view and verifies the captured arithmetic result. It uses an isolated temporary directory. No actual command from the recording is executed.

`python tools/regenerate_examples.py --check` checks the public projections and JSON indexes against the bundled code. Native formatting in the four historical receipts comes from the installed app and is not regenerated by this smaller runtime.

This run proves on-demand retrieval between two Codex contexts and fresh reads after a source update. The earlier [parent/two-child inspection run](controlled-run.md) is supplementary historical evidence, not the primary demonstration.
