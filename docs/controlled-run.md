# Controlled Codex run

This sample is a real, bounded Codex run over this repository's synthetic fixtures. A `gpt-6.1-terra` parent launched two `gpt-6-luna` children: `call_pairing` checked the pending-to-complete tool-call replay; `scope_snapshot` checked compact/detailed selection and snapshot paging. The parent independently checked the same detailed scope before and after an append, addressing a limitation in the child's first comparison. The checks passed in the run. They establish behavior on the invented fixtures, not compatibility with all provider formats or the full app's live refresh.

The captured file reads show the repository as it stood during that run, before this sample was added. It then had six tests. The current suite incorporates the same-scope check and adds a seventh test verifying the published sidecar, segment boundaries and artifact hashes.

Start with [the compact assembly](../examples/controlled-run/assembled.compact.txt), then compare [the detailed assembly](../examples/controlled-run/assembled.detailed.txt). Each assembly labels three separately rendered scopes: parent and two linked children. This explicit assembly is not the native renderer's automatic child embedding. The original prompt is included only in the parent; child task messages were encrypted in the persisted records and are omitted. The prompt was extracted from the input element of the controlled task's creation result; surrounding delegation metadata was excluded.

The structured attachment is [its production-built JSON index](../examples/controlled-run/structured-attachment.json) and [its required raw sidecar](../examples/controlled-run/assembled.detailed.raw.txt). This is the production builder's default `raw_sidecar_plus_index` carrier: the sidecar is exactly the assembled detailed text, while the JSON indexes it. It is not a single self-contained JSON clip. For this input, the detailed source is 149,482 bytes and the formatted index is about 227 KB. The parent and child scopes can also be read separately in the sample directory.

## Selection and limits

The source authority is the three specified local Codex JSONL sessions, not a Claude host run. Claude behavior in this repository is tested with synthetic Claude-shaped records. Thread IDs and model observations are in the [selection receipt](../examples/controlled-run/selection-receipt.json); child-to-parent relationships were verified in the child session metadata. That receipt records source hashes, record counts, categories and an aggregate hash of omitted records without publishing those records.

The inputs retain task lifecycle events, assistant commentary and final answers, tool calls and recorded results. They omit injected instruction and environment messages, system/developer messages, reasoning records, telemetry and collaboration-message records. Encrypted content and encrypted collaboration arguments were removed or replaced with an omission marker. Workspace and temporary paths were replaced with descriptive placeholders. The parent prompt is a selected source element and was placed into a constructed user-message event; the session metadata in each input is also constructed. This is a **selected and sanitized sample**, not a complete or lossless copy of the original sessions. Some recorded command outputs may themselves have been truncated at capture. An omitted event or unavailable result should not be inferred from this sample.

The original provider-shaped records in this directory are reproducible inputs for the extracted parser, but the production compact and detailed renderers are not vendored here. They were run independently on each selected file, with automatic child discovery disabled and the scope child's two turns merged; the resulting texts were then assembled with labels. The renderer's generated diagnostics are interpretations of the selected text, not independent proof of file changes. The original source logs were not modified. [`provenance.json`](../examples/controlled-run/provenance.json) records source hashes, renderer and builder names, output hashes and byte sizes; [`selection-receipt.json`](../examples/controlled-run/selection-receipt.json) records the filtering and replacements. Secret scans are useful checks, not proof that an export is safe for release.
